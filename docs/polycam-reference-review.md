# TerraView: разбор предоставленного экрана Polycam

Основание — пользовательский скрин экрана съёмки объекта из разговора. Два других изображения показывают GitHub Billing и не являются интерфейсом Polycam. Здесь анализируется один экран, а не весь пользовательский путь или весь функционал конкурента.

Видимые сильные решения: большая область камеры; отдельные советы и выход; короткое указание следующего действия поверх камеры; центральный прицел; крупная круглая кнопка записи; выбор режима снизу. В скрине нет доказательства работы этих режимов, качества mesh или скрытых настроек.

В TerraView применены эти принципы: камера до начала записи, заметная кнопка и состояние записи, советы, выбор LiDAR/план/фото; отдельный настоящий Object Capture с системными границами и направляемым обходом. Подсказки зависят от отслеживания, расстояния, движения и света. Цветная сетка появляется после записи исходника; обнаруженная плоскость обозначается отдельным пунктиром.

Проблема прежнего LiDAR из сообщения оператора подтверждена кодом: debug-сетка RealityKit рисовала диагонали, а 2D-контуры не отсекались около камеры. Debug overlay удалён, заливка имеет собственный ограниченный renderer, потолочные/дальние контуры исключаются, остальные сегменты отсекаются перед и после проекции. Визуальные ограничения не изменяют исходную геометрию.

Малые кнопки имеют доступные подписи; состояние не зависит только от цвета; невидимая/недоступная камера получает явный экран и восстановление. Контраст live-камеры и физическая доступность должны проверяться на iPhone при разных условиях освещения. Актуальные Simulator-снимки будут просмотрены отдельно; скрин Polycam не подменяет проверку TerraView.
